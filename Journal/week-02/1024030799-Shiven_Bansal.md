# Week 2 — P3: Entity-Linked Graph Structure

## Planned Objective

Implement the entity-linked graph structure in NetworkX using hardcoded/mock flagged events.

## Work Completed

- Implemented the initial entity-linked event graph using NetworkX.
- Used a directed graph to represent the order of security events.
- Added event nodes containing the event information as node attributes.
- Implemented relationships between events based on shared entities such as:
  - User
  - IP address
  - Session
- Added time-window considerations when correlating related events.
- Tested the graph structure using mock flagged events.

## Cross-Module Validation

As an additional step, the correlation engine was tested against the current output of the P2 simulator.

This exposed several interface mismatches between the initial P3 implementation and the shared event schema:

- P3 initially expected `source_ip`, while the canonical schema uses `ip`.
- Some P3 attack templates used event names that did not match the canonical `event_type` values.
- P2 produces timestamps as ISO-formatted strings, while the initial P3 implementation expected Python `datetime` objects.

These issues were corrected so that P3 follows the canonical event schema.

## Integration Testing

Added an integration check to verify that P3 can consume events generated by the P2 simulator.

The test was used to:
- Pass simulator-generated events into the correlation engine.
- Verify that events are correctly added to the entity-linked graph.
- Test correlation using real simulator output rather than only hand-written mock events.
- Validate an attack sequence and its reconstruction into an incident.

## False-Positive Observation

During testing with normal simulator traffic, the initial data-exfiltration pattern produced false positives because a normal sequence could contain:

`login → db_query → file_access`

The pattern was refined to distinguish downloaded files from ordinary file access using the event metadata.

This reduced false positives during the integration test.

## Key Concepts Learned

- NetworkX directed graphs.
- Node and edge attributes.
- Entity-based event correlation.
- Temporal relationships between security events.
- Using a shared event schema between independent modules.
- Importance of cross-module testing.

## Current Status

The P3 correlation module can now build an entity-linked graph and consume events following the canonical event schema. The module has also been tested against actual simulator-generated events from P2.
